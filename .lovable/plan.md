# FiqhGPT — Advanced Islamic Jurisprudence Chatbot

A ChatGPT-style assistant with three modes (Fatwa, Faraid, Zakat), answers grounded in Arabic reference books you upload, and an admin library panel. Works on desktop and phone with the same layout language as ChatGPT.

## What you get

**Chat experience (ChatGPT-style)**
- Left sidebar with conversation history, new-chat button, collapsible on desktop, slide-over drawer on mobile.
- Centered message column, streaming answers, copy/regenerate actions, sticky composer at the bottom.
- Mode switcher at the top of every new chat: **Fatwa / Faraid / Zakat**.
- **Temporary chat** — nothing saved, no account needed, cleared when the tab closes.
- **Signed-in chat** — email sign-up with a verification email; conversations and messages saved to your account and listed in the sidebar.

**Fatwa mode**
- School selector: General, Shafi'i, Hanafi, Maliki, Hanbali.
- A specific school answers only from that school's books.
- **General** researches all four schools, presents each school's ruling separately, notes where they agree and differ, then gives a balanced summary.
- Every answer cites the book, chapter/page, and quotes the original Arabic passage.

**Faraid mode**
- Inheritance rulings plus the actual arithmetic: heirs entered or described in plain language, shares computed with the classic method (asl al-mas'ala, correction/tashih, radd and 'awl handled), shown as a share table with fractions and amounts.
- Legal reasoning cited from the uploaded books.

**Zakat mode**
- Zakat al-mal (wealth: cash, gold, silver, trade goods, livestock, crops) with nisab checks and computed amount due.
- Zakat al-fitr (body) with per-person measure and monetary equivalent.
- Both explain the ruling with citations alongside the calculation.

**Answer language:** explanation in English, original passages quoted in Arabic.

**Admin panel (your email only)**
- Upload kithabs as PDF or plain text/Word.
- Tag each book: school (Shafi'i / Hanafi / Maliki / Hanbali / general), topic (Fatwa / Faraid / Zakat / general), author, title, notes.
- Files stored on Cloudinary; text extracted, split into passages, and indexed for Arabic search so answers are generated by analyzing your books.
- Book list with processing status, passage counts, re-index and delete.
- Usage view: recent questions per mode.

## Best format for the kithabs

Upload **plain text (UTF-8) or Word** whenever you have it — Arabic PDF scans need OCR and lose diacritics and line structure, which weakens retrieval accuracy. Recommended shape per file: one book per file, chapter headings on their own line prefixed with `##`, and page markers like `[ص ١٢٣]` where known — the importer uses those to build accurate citations. PDFs are still accepted; digital (text-layer) PDFs work well, scanned images are OCR'd with lower confidence and get flagged in the admin list.

## Technical notes

- **Backend:** Lovable Cloud (Supabase) — Postgres, email/password auth with verification, row-level security.
- **Tables:** `profiles`, `user_roles` (+ `has_role` function, admin by email), `conversations`, `messages`, `books`, `book_chunks` (with `tsvector` + `pgvector` embedding column), `zakat_rates`, `usage_events`. All with explicit grants and RLS; users read only their own chats, books readable by authenticated users, writable by admin only.
- **Retrieval:** hybrid search — Arabic-normalized full-text (`simple` config with diacritic/alef stripping) + vector similarity via `google/gemini-embedding-2`, results filtered by school and topic tags, top passages injected into the prompt with citation metadata.
- **Model:** `openai/gpt-6-astra` on the Lovable AI Gateway using your own Gemini key path is not applicable, so the chat calls go through the gateway Responses API with streaming; your Gemini key is stored as `GEMINI_API_KEY` and used for embedding/extraction work. If you prefer all calls on your Gemini key, say so and I'll route the chat there too.
- **Server boundaries:** streaming chat at `src/routes/api/chat.ts`; `createServerFn` for conversation CRUD, Cloudinary signed uploads, book ingestion, Faraid and Zakat calculators (deterministic math in code, not left to the model).
- **Cloudinary:** `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` stored as secrets; uploads signed server-side, files stored as raw resources, never exposed to the browser.
- **Faraid engine:** pure TypeScript module with unit tests covering fixed shares, 'asaba, hajb, 'awl and radd cases.
- **UI:** AI Elements chat primitives, custom design tokens (deep green / warm parchment palette, Arabic-capable serif for quotes), no Lovable branding anywhere.
